# DATA — sources, products and exact file contracts

All browser-facing products live under `data/web/` and are served at `/data/...`
(Vite dev server, nginx in docker compose, or any static host). Producers are the
`pipeline/jobs/*` scripts; consumers are `apps/web` and `services/compute`.
**This file is the contract — change it first, then both sides.**

## 1. Reference frame, heights, projection

- Body-fixed frame: **MOON_ME** (mean Earth / polar axis). LOLA products are in
  DE421 MOON_ME; our ephemerides use `MOON_ME_DE440_ME421` (NAIF `moon_de440_250416.tf`),
  which is the DE440 libration realisation aligned to DE421 ME (differences at the
  metre level on the surface). MOON_PA vs MOON_ME differ by up to ~0.9 km on the surface.
- Reference sphere `R = 1737400 m`. Heights are metres above that sphere.
- Map projection: **south polar stereographic** on the sphere, true scale at the pole:
  `+proj=stere +lat_0=-90 +lon_0=0 +k=1 +x_0=0 +y_0=0 +R=1737400 +units=m +no_defs`
  (identical to the PGDA GeoTIFFs; code name in the app: `LUNAR:SPS`).
  - Forward (lat φ ≤ 0, lon λ east-positive): `c = 90° + φ` (angular distance from the
    pole), `ρ = 2R·tan(c/2)`, `x = ρ·sin λ`, `y = ρ·cos λ`.
    Lon 0° (toward Earth) points to +y ("up"), lon 90°E to +x.
  - Inverse: `ρ = hypot(x,y)`, `c = 2·atan(ρ/2R)`, `φ = c − 90°`, `λ = atan2(x, y)`.
  - Unit vector (MOON_ME) without trig: with `q = ρ²/(4R²)`:
    `u = ( (y/R)/(1+q), (x/R)/(1+q), −(1−q)/(1+q) )`.
  - Scale factor `k = 1 + q` (true distance ≈ grid distance / k).
- Local frame at a point: `Up = u`, `East = (−sin λ, cos λ, 0)`,
  `North = (−sin φ cos λ, −sin φ sin λ, cos φ)`. Azimuth A is clockwise from North.
  In grid coordinates North = `(sin λ, cos λ)` (radially away from the pole) and
  East = `(cos λ, −sin λ)`; a ray of azimuth A runs along grid direction `(sin(λ+A), cos(λ+A))`.

## 2. DEM tile pyramid — `data/web/dem/`

Grid **LPS-2560** (aligned with the PGDA 80/40/20/5 m grids, whose pixel edges sit on
multiples of the pixel size from the pole):

| z | res (m/px) | tiles per side | source |
|---|---|---|---|
| 0 | 2560 | 1 | 2×2 mean of z1 |
| 1 | 1280 | 2 | 2×2 mean |
| 2 | 640 | 4 | 2×2 mean |
| 3 | 320 | 8 | 2×2 mean |
| 4 | 160 | 16 | 2×2 mean |
| 5 | 80 | 32 | `LDEM_80S_80MPP_ADJ.TIF` (native) |
| 6 | 40 | 64 | `LDEM_80S_40MPP_ADJ.TIF` (native; falls back to bilinear z5 if absent) |
| 7 | 20 | 128 | 2×2 mean of z8 (site areas only) |
| 8 | 10 | 256 | 2×2 mean of z9 (site areas only) |
| 9 | 5 | 512 | 5 m site DEMs (`*_final_adj_5mpp_surf.tif`, sites only) |

- Origin (top-left corner): `X0 = −327680 m`, `Y0 = +327680 m`; tile size `T = 256` px.
- `res(z) = 2560 / 2^z`. Tile `(z, tx, ty)` covers
  `x ∈ [X0 + tx·T·res, X0 + (tx+1)·T·res]`, `y ∈ [Y0 − (ty+1)·T·res, Y0 − ty·T·res]`;
  row 0 is the **top** (max y). Pixel `(row i, col j)` centre:
  `x = X0 + (tx·T + j + 0.5)·res`, `y = Y0 − (ty·T + i + 0.5)·res` (pixel-is-area).
- Only tiles that intersect data are written. z7–z9 tiles exist only around 5 m sites;
  pixels a site DEM does not cover are **filled** from z6 (bilinear) so every written
  tile is complete. Nodata only outside the LOLA coverage (beyond ≈80°S).
- Path: `data/web/dem/{z}/{tx}/{ty}.bin`
- File = **gzip** of the payload below (the client inflates it when it sees the gzip
  magic `1f 8b`; if a server already decoded it, the payload is used as-is).
  Payload, little-endian:

  | offset | type | field |
  |---|---|---|
  | 0 | 4×u8 | magic `LDT1` |
  | 4 | f32 | `base` (m) |
  | 8 | f32 | `scale` (m per unit) |
  | 12 | u16 | width (=256) |
  | 14 | u16 | height (=256) |
  | 16 | i16[h][w] | value; `−32768` = nodata; `height_m = base + scale·value` |

  The producer chooses `base = (min+max)/2` and `scale = max(0.01, (max−min)/65000)`
  per tile, so quantisation error ≤ scale/2 (≤ 5 mm for most tiles).
- Index `data/web/dem/index.json`:
  ```json
  {"version": 1,
   "grid": {"name": "LPS-2560", "x0": -327680, "y0": 327680, "tileSize": 256, "res0": 2560,
            "radius": 1737400, "proj4": "+proj=stere +lat_0=-90 +lon_0=0 +k=1 +x_0=0 +y_0=0 +R=1737400 +units=m +no_defs"},
   "coverage": {"maxRho": 304000, "minLatDeg": -80.0},
   "levels": [{"z": 5, "res": 80, "source": "LDEM_80S_80MPP_ADJ.TIF", "native": true,
               "tiles": [[tx, ty], ...]}, ...],
   "heightRange": [-5400.0, 6200.0],
   "error": {"available": true, "maxZ": 5, "path": "err"},
   "generated": "ISO-8601", "job": "pipeline/jobs/dem_tiles.py"}
  ```
- Height error tiles (optional, from `*_ERR.TIF`, 1-σ metres): same grid and format at
  `data/web/err/{z}/{tx}/{ty}.bin` for z ≤ 5.

## 3. Ephemeris tables — `data/web/ephem/`

- Generated by `pipeline/jobs/ephemeris.py` with SpiceyPy: kernels `naif0012.tls`,
  `de440s.bsp`, `moon_pa_de440_200625.bpc`, `moon_de440_250416.tf`, `pck00011.tpc`.
- `spkpos(target, et, "MOON_ME", "LT+S", "MOON")` for target `SUN` and `EARTH`
  (apparent geocentric-of-Moon positions, km). Topocentric correction is done by the
  consumer (subtract the site vector — essential for Earth: up to 0.26° parallax).
- Uniform **UTC** grid: `2026-01-01T00:00:00Z` → `2037-01-01T00:00:00Z`, step **1800 s**.
- One file per calendar year: `data/web/ephem/{YYYY}.bin`, raw little-endian float32,
  records of 6 floats: `[sunX, sunY, sunZ, earthX, earthY, earthZ]` (km, MOON_ME).
  Record `k` of year Y is at `Date.UTC(Y,0,1) + k·1800 s`; the file has exactly
  `(days in Y)·48` records.
- Consumers interpolate linearly between records (direction error: Sun ≤ 0.017″, Earth ≤ 0.121″ —
  the Earth term comes from libration acceleration; verified in `docs/VALIDATION.md`).
- Index `data/web/ephem/index.json`:
  ```json
  {"version": 1, "frame": "MOON_ME", "frameRealization": "MOON_ME_DE440_ME421",
   "observer": "MOON (301) centre", "aberration": "LT+S", "units": "km", "stepSeconds": 1800,
   "record": ["sunX","sunY","sunZ","earthX","earthY","earthZ"], "dtype": "float32-le",
   "startUtc": "2026-01-01T00:00:00Z", "endUtc": "2037-01-01T00:00:00Z",
   "years": [{"year": 2026, "url": "2026.bin", "records": 17520, "sha256": "..."}],
   "kernels": ["naif0012.tls", "..."], "sunRadiusKm": 695700.0, "earthRadiusKm": 6371.0084,
   "generated": "ISO-8601"}
  ```

## 4. Site catalog — `data/web/sites.json`

Curated in `pipeline/config/sites.json`, enriched by `pipeline/jobs/sites.py`
(5 m DEM centres/extents, coverage flags):
```json
{"version": 1, "sites": [
  {"id": "site04", "name": "Shackleton rim", "lat": -89.78, "lon": -156.2,
   "kind": "pgda-5m|artemis|clps|mission|reference",
   "coordQuality": "dem-summit|dem-centre|published|approx",
   "inCoverage": true, "hiRes": {"z": 9, "bbox": [xmin, ymin, xmax, ymax]},
   "note": "short plain-language note", "source": "URL"}]}
```
Sites outside the LOLA polar coverage keep `"inCoverage": false` and are listed as
"outside coverage" (no horizon can be computed). PGDA 5 m sites use `dem-summit` = highest terrain
inside the central 60% of the site DEM (ADR in DECISIONS.md); extra fields: `x`, `y`, `heightM`,
`demCentre`, `demBbox`, `dem`.

## 5. Permanently shadowed regions — `data/web/psr.geojson`

`LPSR_80S_20MPP_ADJ_1km2` polygons, coordinates in **LUNAR:SPS metres**, simplified to
≤ 20 m tolerance, properties `{area_km2}`. Overlay only.

## 6. Pre-baked suitability heatmaps — `data/web/heatmaps/`

Static fallback for `services/compute` (`POST /api/v1/heatmap` returns the same format):
- `data/web/heatmaps/index.json`: `{"items": [{"id", "preset", "t0", "t1", "footprintM",
  "url": "<id>.png", "meta": "<id>.json"}]}`
- `<id>.png`: RGBA, colormapped score (transparent = fails a hard constraint or no data).
- `<id>.json`: `{"bbox": [xmin, ymin, xmax, ymax] (SPS m), "res": m, "width", "height",
  "params": {...}, "legend": {"min": 0, "max": 1, "colormap": "cividis"},
  "candidates": [{"x", "y", "lat", "lon", "score", "rankStability"}], "stats": {...}}`
- `<id>.score.bin` (optional): gzip of `float32[height][width]` raw scores (NaN = excluded).

## 6b. Statistical micro-relief — `data/web/micro/` (display only)

`index.json` (`version`, `method`, per tile: `file`, `size`, `meters`, `levels`, `params`, `stats`) and one
`<tile>.bin` per tile: gzip of float16 LE, 2 channels (`ground`, `rocks`, metres) interleaved, mip levels
(2×2 means, `size` … 1) concatenated. Tiles are periodic (seamless). `coarse`: 32 m / 1024² (3.1 cm px;
craters 0.25–5 m, boulders 0.15–2 m); `fine`: 4 m / 1024² (3.9 mm px; craterlets 4–60 cm, pebbles 1–15 cm).
Built by `pipeline/jobs/micro_relief.py` (deterministic seeds, ≈ 2 s). Never used by metrics.

## 6c. Context Moon outside the polar coverage — `data/web/outer/` (display only)

`index.json` (`file`, `x0`, `y0`, `res`, `n`, `maxRho`, `latMax`, `source`) and `dem.bin`: one LDT1 raster
(gzip, row 0 = +y edge) in the same SPS frame, 2048² × 3398 m out to the equator (ρ ≤ 2R), heights above
1737.4 km. Source: LOLA global GDR `ldem_16.img` (16 px/deg, PDS Geosciences Node; `sources.json`
`ldem-global-16`), 3×3 point-sample mean per pixel. Built by `pipeline/jobs/outer_dem.py` (≈ 3 s).
Used only by the map's display pass for pixels outside the coverage; analysis and metrics never see it.
Seam check at ρ = 290 km vs the polar z0 tiles: mean 6 m, RMS 212 m (resolution difference).

## 7. Server-side work products — `data/work/` (never shipped to the browser)

- `horizon_{res}m.npy` + `.json`: region horizon map, `uint8[ny][nx][naz]` —
  elevation `e = −5° + 0.1°·v` (`v = 255` means ≥ 20.4°), naz = 64 by default,
  azimuth `k·360/naz` (clockwise from local North), observer height 2 m.
- `features_{res}m.npz`: slopeMax, slopeMean, relief, height and a PSR mask for the same grid.

## 8. Manifest — `data/manifest.json` (committed)

`{"version": 1, "files": {"<id>": {"url", "path", "size", "sha256", "license",
"description", "job", "fetched_utc"}}, "products": {"<name>": {"path", "sha256", "job"}}}`.
`make data-pull` restores processed products from `DATA_BASE_URL` using this file
instead of recomputing (cloud-agnostic; any static file host works).
